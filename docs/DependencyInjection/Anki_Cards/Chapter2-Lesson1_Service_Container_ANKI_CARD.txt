"What happens if a service alias is defined via the #[AsAlias] attribute on a class, but a different alias for the same interface is explicitly set in services.yaml?"	"The YAML configuration takes precedence and silently overrides the PHP class attribute."
"When using the #[Target('invoice_pdf')] attribute to resolve an ambiguous interface implementation, what must the target class declare?"	"The target must be registered as a named autowiring alias with the id InterfaceName $invoicePdf (the name is converted to camelCase; a plain alias invoice_pdf is not enough). Otherwise, compilation fails with a RuntimeException."
"Why might a correctly configured private service disappear from debug:container <Service-ID> even though cache:clear runs without errors?"	"The RemoveUnusedDefinitionsPass removed it. If a private service is not injected into any active framework entry point (like a Controller or Command), Symfony purges it from the compiled container during optimization."
"What two configuration keys are set by default under the _defaults: block in a standard Symfony services.yaml?"	"autowire: true (resolves dependencies via reflection) and autoconfigure: true (automatically adds tags based on class hierarchy). Services are private by default, so public: false is not needed."
"Look at this service class constructor utilizing a core DI attribute:

namespace App\Manager;
use Psr\Log\LoggerInterface;
use Symfony\Component\DependencyInjection\Attribute\Target;

class OrderManager {
    public function __construct(
        #[Target('localLogger')]
        private LoggerInterface $appLogger
    ) {}
}

What determines whether this dependency autowires successfully: the attribute string argument 'localLogger' or the native PHP variable name $appLogger?"	"The attribute string 'localLogger' determines success. Reason: The #[Target] attribute explicitly instructs the compiler pass to look for the named autowiring alias Psr\Log\LoggerInterface $localLogger. Once #[Target] is explicitly defined, the actual variable name ($appLogger) is completely ignored by the container's dependency resolution mechanics."
