"What is the primary architectural benefit of using Dependency Injection over hardcoding class instantiations?"	"It achieves loose coupling, making classes highly testable and maintainable by decoupling a class from its dependencies' creation logic."
"What is the structural difference between a Service Definition and a Compiler Pass inside the DI container?"	"A Service Definition is the configuration blueprint for a single service, whereas a Compiler Pass is a PHP class that can manipulate multiple definitions at once during container compilation."
"Look at this configuration mix inside a Symfony 8 project:

# config/services.yaml
services:
    App\Service\AnalyticsService:
        autowire: false

// src/Service/AnalyticsService.php
namespace App\Service;
use Symfony\Component\HttpFoundation\ChainRequestMatcher;

class AnalyticsService {
    public function __construct(private ChainRequestMatcher $matcher) {}
}

What happens when Symfony attempts to compile the service container?"	"The container compilation succeeds, but creating the service later fails with an ArgumentCountError (too few arguments). Reason: The explicit autowire: false declaration in services.yaml completely disables the framework's automatic type-hint resolution for this specific service. Symfony will not attempt to guess or inject the ChainRequestMatcher dependency, so the constructor is called without it. (An unused private service is removed during compilation and never fails.)"
"True or False: If a service class contains no PHP attributes but has clear type-hints in its constructor, setting autowire: true (or relying on _defaults: autowire: true) in services.yaml is fully sufficient for Symfony to register and resolve its dependencies."	"True. Standard autowiring in Symfony relies purely on native PHP type-hints. Core PHP attributes (like #[Target] or #[AsAlias]) are only necessary when you need to resolve structural ambiguities, define specific non-standard injection keys, or create custom aliases."
