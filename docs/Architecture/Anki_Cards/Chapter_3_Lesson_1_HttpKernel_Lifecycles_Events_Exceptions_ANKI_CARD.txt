"Which design pattern does the Symfony HttpKernel component primarily implement to handle a Request?"	"The Mediator pattern (via the EventDispatcher) to decouple the Request/Response lifecycle from specific controller logic."
"What is the precise structural difference between a 'Main Request' and a 'Sub Request' in Symfony 8?"	"A Main Request is the initial HTTP request entering the application. A Sub Request is triggered internally (e.g., via forwarding or rendering fragments) and does not restart the entire PHP server lifecycle."
"What happens if a listener on the kernel.request event sets a Response object on the event?"	"The HttpKernel stops event propagation immediately, controller resolution is skipped, and it proceeds directly to the kernel.response phase."
"What is the primary technical purpose of the kernel.controller_arguments event?"	"It allows listeners to inspect, modify, or completely swap the arguments (resolved via Value Resolvers) before they are passed into the controller."
"Look at this Event Subscriber implementation targeting the KernelEvents::REQUEST pipeline:

use Symfony\Component\EventDispatcher\EventSubscriberInterface;

use Symfony\Component\HttpKernel\KernelEvents;

class EarlyMaintenanceSubscriber implements EventSubscriberInterface {
    public static function getSubscribedEvents(): array {
        return [KernelEvents::REQUEST => ['onKernelRequest', 512]];
    }

    public function onKernelRequest(RequestEvent $event): void {
        // Condition checking
    }
}

If this subscriber detects a maintenance state and needs to immediately return a custom maintenance HTML page to the browser without letting subsequent listeners or the controller execute, which method must be called on the $event object?"	"You must call $event->setResponse(new Response('Maintenance Mode'));. Calling setResponse() stops further propagation of the event implicitly and prevents the HttpKernel from executing the controller, jumping directly to the response deployment phase."
"During the HttpKernel lifecycle, if a listener assigned to the KernelEvents::CONTROLLER event replaces the controller completely, what specific PHP type validation does Symfony enforce on the object passed into $event->setController()?"	"Symfony enforces that the value must be a valid PHP callable (an anonymous function, an instance of an invokable class, or an array mapping [$instance, 'method']). If a non-callable is passed, a TypeError is thrown immediately."
